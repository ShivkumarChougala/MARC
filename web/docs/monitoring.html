Using MARC / Monitoring

Monitoring

Understand your Mac’s activity without opening a terminal.

Status

Start with Status for CPU and memory readings, load and swap, network and disk activity, Services & Docker, and top processes. Battery and SSD readings appear beside the Mac name when enabled and available. Tap CPU or Memory to switch to load or swap. Availability depends on the Mac and the readings it exposes.

System

Use System for per-core CPU activity, uptime, load, memory, swap, network, storage, and user information.

Statistics and history

Statistics shows activity over time. MARC stores history on the connected Mac under the SSH account:

History location
~/.local/share/marc/history.sqlite

Removing a Mac profile from iPhone does not delete this remote history or the Mac’s files.

Services and top processes

Status previews listening TCP ports or Docker containers. Open All services or All containers for the full list and available actions. Read Services & Docker for requirements and supported controls.

Top processes shows names, PIDs, CPU and memory use. View all opens Processes sorted by CPU.

Reading the numbers

  • CPU: how busy the processor is. A short spike during an app launch or build is normal; sustained activity is more useful to investigate.
  • Memory: RAM used by apps and the system. A high number alone does not identify a problem—look at what is running and whether the Mac feels slow.
  • Swap: disk space macOS uses to support memory. It is different from physical RAM.
  • Storage: space used and available on a drive.
  • Network: activity moving through the Mac’s network connection.
  • Uptime: how long the Mac has been running since its last boot.

When something looks unusual

Look for a pattern rather than reacting to one reading. If CPU or memory stays high, open Processes and sort by that resource to see which apps are active.

Check storage separately if the drive is nearly full. Closing an app may reduce its memory use, but it does not remove files from the drive.

What monitoring history contains

The monitoring collector attempts to save a sample about every five seconds in ~/.local/share/marc/history.sqlite under the SSH account. Alongside activity readings, the payload can include hostname, username, local IP address, hardware and operating-system details, network interface, uptime and power readings.

While active, the collector periodically prunes its own rows older than two hours. Stopping monitoring does not schedule deletion. The database and older collector tables remain; row deletion does not erase backups. Removing a saved Mac does not remove remote history. The Mac account owner can remove the database separately.

What history tells you

History shows recorded samples, not every moment of activity. Connection interruptions and collection problems can leave gaps.

History is saved under the connected SSH account. Connecting to another Mac or another account can show a different history.

Missing or stale readings

Check that the connection is active and Python 3 is available to the SSH account. Keep the Mac awake. A missing reading can reflect a permissions or collection problem rather than zero usage.
